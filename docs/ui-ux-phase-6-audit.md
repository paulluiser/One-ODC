# One ODC — Phase 6A UI/UX audit and design direction

Date: 14 October 2026 · Scope: initial release, approximately 50 users · **Audit only; Phase 6B implementation has not begun.** Business logic, API behavior, RLS, financial calculations and production configuration are unchanged.

## A. Current assessment and evidence

One ODC already has a recognizable identity: Deep Blue navigation, restrained architectural linework, the existing wordmark and an effective login composition. The workspace needs stronger task hierarchy and more deliberate information density. Repeated full-width cards, small secondary text and exposed technical history make important work harder to locate.

38 representative screenshot captures support this audit. Read-only staging inspection used the existing Admin, BDM, Lead Designer, Designer and Operations Admin accounts. Only authentication and local UI state changed; no invitation, lead, project, payment, supplier, upload or lifecycle operation was submitted. Existing synthetic staging records were used, not production/customer data. UUIDs embedded in fixture **names** exaggerate title length; do not rewrite stored names as a visual fix.

Evidence: [screenshot inventory](../artifacts/verification/phase6a-ui/manifest.json), [focused accessibility/keyboard checks](../artifacts/verification/phase6a-ui/checks.json), [computed sign-out styles](../artifacts/verification/phase6a-ui/sign-out-styles.json). Screenshots are local audit evidence, not proposed designs.

## C. Recommended visual direction

**A precise architectural workspace:** retain the existing One ODC mark, “Every space. One vision.” and **#2663D8** primary accent. Use navy for structure, warm stone/gold sparingly for identity, and neutral surfaces for work. Avoid dashboard decoration, photographic backgrounds behind controls, glass effects and a different accent color for every card.

Composition: a quiet 64 px context header; 240 px desktop sidebar; page title, concise explanation and one primary action; then the current task and its working data. Use aligned edges and thin section rules rather than nested card frames. Brand/editorial expression belongs primarily in entry screens; forms, quotes and ledgers prioritize readability.

Proposed Project order: **Project identity + independent commercial/operational states → workspace navigation → current authorized summary/next action → Spaces or selected tab data → Activity/history on demand.** Ops must still receive only safe preview before closure; do not fetch forbidden data merely to hide it visually.

## G. Accessibility findings and verification limits

**P0 confirmed — navy sidebar focus contrast.** Keyboard inspection confirmed `:focus-visible`, a 3 px outline `#2663D8`, and adjacent navy `#14233D`: **2.88:1**. It misses the 3:1 adjacent-color threshold for an authored focus-state indicator. Scope a `--focus-on-navy: #92B9FF` token to both light and dark navy sidebars; test selected items, sign-out, mobile drawer and all navigation controls. [WCAG 2.1 non-text contrast guidance](https://www.w3.org/WAI/WCAG21/Understanding/non-text-contrast.html).

**Phase 5A sign-out text question resolved for sampled state.** Computed text is `#B5C2D7` at 12 px/500 over transparent ancestors ending at opaque navy `#14233D`; opacity is 1, no background image. Text contrast is **8.72:1**, exceeding the normal-text requirement. The fresh Admin scan did not reproduce the old inconclusive text-contrast result. Keep the text palette; fix the separate focus outline. Ratios use sRGB relative luminance from computed colors, not anti-aliased screenshot pixels. [Contrast guidance](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html).

**P0 verification gate — modal assistive technology.** Eight Tab presses remained in the non-submitted Reopen dialog; Escape returned focus to its trigger. Mobile navigation also restored focus. Axe still reports inconclusive `aria-hidden-focus` and `color-contrast` for the dialog; these are not confirmed violations. Before release, manually inspect background exclusion, dialog announcement, keyboard containment, focus visibility and trigger-removal recovery with VoiceOver/NVDA. Do not remove Radix containment to quiet the scanner.

**P1 — labels, announcements and affordances.** Expose the selected Light/Dark/System preference, not only icon actions; increase small support text; reuse visible field styling in Analytics/supplier search; use meaningful activity names and accessible error-summary links. Lead field errors already have `aria-invalid`/`aria-describedby`; extend that existing pattern to other forms. Pending/retry states need consistent polite announcements. [Status-message guidance](https://www.w3.org/WAI/WCAG21/Understanding/status-messages.html).

Observed light/dark/System theme changes work. Sampled desktop, 360 px mobile and 640 px reflow views had no document-level horizontal overflow. A Lead access attempt to the BDM-only new-request route correctly redirected to a denial message; this is separately labeled in evidence, not counted as form inspection. BDM 320 px inspection is separate. Actual browser zoom, real mobile keyboard behavior and screen readers remain unverified. [Reflow guidance](https://www.w3.org/WAI/WCAG21/Understanding/reflow.html).

Five focused axe scans (Admin, quotation comparison, Reopen dialog, Lead role-denial state and BDM form at 320 px) found zero detected violations; the Reopen scan retained two inconclusive rule types. One BDM scan was retried after correcting the audit harness to create an explicit browser context, as required by axe. Automated zero findings do not certify WCAG conformance. Error/pending/network-state specifications above remain source-reviewed proposals, not newly verified live behavior.

## I. Phase 6C acceptance criteria

1. No unresolved P0 defect or unassessed P0 accessibility gate. Explicitly classify every incomplete automated result. Normal text ≥4.5:1, large text ≥3:1 and meaningful control/state indicators ≥3:1 on actual adjacent surfaces.
2. Verify all five role dashboards and role-safe navigation; BDM approved-only quotations, Ops pre-close restrictions and no unauthorized Sale/Raw/file visibility remain unchanged. Direct API/RLS security regression still passes after presentation work.

Check **actual** 200%/400% browser zoom, text spacing, touch use and virtual keyboard. The mobile primary action must not be obscured by sticky chrome.
5. Light/Dark/System are persistent, visibly and semantically selected, and follow OS media changes. Test focus, error, disabled and selected states; reduced motion eliminates nonessential movement.
6. Ordinary dashboard task queues and Project navigation/primary context are visible in the first viewport at 1440×900 and reachable immediately at 360×800. No required action is buried behind unrelated audit history. Historical details remain accessible.
7. Under slow/offline/error conditions, no false zero/success/progress, restricted-content flash, lost entered data or double mutation. Route skeletons match their destination; background refresh keeps usable content; auth callbacks still work safely.
8. File optimization/upload/resume remain distinct and honest; originals, versions, archive/restore, three active slots and 50 MiB cap remain unchanged. Saved lead Notes/HTTPS resources and conversion persist. No background external downloads.
9. Chart labels/data alternatives, money and KPI definitions/denominators match the server and drilldowns. “Not Available” remains distinct from zero; no new analytics is invented by the redesign.
