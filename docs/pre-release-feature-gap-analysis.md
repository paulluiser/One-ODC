## Ranked value versus effort

1. **Unsaved-input protection:** highest loss-prevention value; M effort. Start with BDM lead drafts/resubmission and Notes/resources, then contextual operational forms. Preserve the existing stronger quotation/finance behavior.
2. **Copy Project Link:** XS effort, immediate navigation/coordination value; authenticated URL only.
3. **Helpful recovery:** S effort using existing mappings/boundaries; preserve input and offer safe reload/reconcile rather than blindly repeating a mutation.
4. **PDF/image preview:** M effort, high document-access value. First support JPEG/PNG/WebP and PDFs through safe browser-native rendering; retain downloads and unsupported/large-file fallback. Universal PDF tooling is not required.
5. **Short role help:** S effort, high first-cohort value. Answer where to update Space status, review quotations, acknowledge handoffs, upload files and obtain access.
6. **Remember filter defaults:** S; valuable convenience, but URL refresh/share already works. Optional, never a reason to delay pilot.
7. **Limited global search:** M; useful once directory navigation is demonstrably repetitive. Start with authorized projects and eligible leads, not a new enterprise index.
8. **Local favorites/recent history:** S; optional alternative to search, not automatically both.
9. **CSV:** S–M; ship only for a validated reporting use case with explicit field/row scope.
10. **Structure templates:** L; validate repeated structures first.
11. **Comments/@mentions:** L; defer new collaboration semantics.

## Explicit deferrals and release risks

- Defer comments/@mentions, project templates, cross-device favorites/preferences, financial CSV, broad search/indexing and advanced document editing until after release or a separately approved need.
- **UI-R5 is now visually approved.** That resolves the visual gate only. Manual screen-reader/actual browser-zoom assessment, invitation-link/password onboarding and deployment configuration remain outstanding.
- Historical intermittent staging-read cause remains unknown despite healthy bounded reads and the successful UI-R5 suites. New retries must not hide errors or duplicate financial saves. Forced-outage recovery is not yet proven.
- Unsaved protection is inconsistent today; operation dialogs can reset unsaved edits on close. This is a pre-pilot usability/data-loss risk, not evidence of a database integrity defect.
- Private file downloads work, but previews and representative real architectural-document testing remain unverified. Signed URLs are bearer links until expiry; preview must not weaken access checks or extend their lifetime casually.
- Production remains intentionally unchanged. Staging verification does not establish production migrations, feature flags, SMTP/auth redirects, capacity or deployment readiness. No production query or migration was performed for this audit.

**M1 readiness:** sufficient reusable code and evidence exist to implement the narrow batch without a planned schema change. Before coding, approve the batch and its form coverage; do not broaden it automatically. No new functional tests were executed for M0, and no feature is reported as newly delivered.
